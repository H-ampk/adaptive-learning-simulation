# 生成学習者モデル

生成学習者モデル（Generative Learner）は、シミュレーション上の世界です。練習、知識の変化、観測される回答を生み出します。評価対象のモデル（BKT、PFA、HLR など）は、その世界に適合させるか、その世界に対して採点します。世界そのものを定義するのは、評価対象のモデルではありません。

## 設計原則

- BKT、PFA、HLR のいずれも、真のデータ生成モデルとしては使わない。
- 評価対象のモデルと生成世界は、独立したままにする。
- 頑健性は複数の世界にわたって見る。結果が一つの学習仮定の産物にならないようにするためである。

一つの世界は、学習の規則、忘却（Forgetting）の規則、時間を明示するかどうかを述べます。それらの仮定を変えることは、世界を変えることです。採点されるモデルの隠れたパラメータを変えることではありません。

## 潜在状態

この節は確定した研究仕様です。

生成学習者の学習者 `u`、概念 `c`、時刻 `t` に対する真の潜在状態は次です。

```text
K[u, c, t] ∈ [0, 1]
```

`K` は連続的な潜在コンピテンス・保持状態です。BKT の `P(L)` とは同一視しません。`P(L)` は、二値の learned / unlearned 状態に対する mastery probability です。`K` はその確率ではなく、連続量としてのコンピテンスと保持の状態です。BKT、PFA、HLR のいずれかの内部状態も、生成世界の真値としては採用しません。

### `a` は派生値

`a` は保存状態ではありません。必要時に次で計算します。

```text
a = logit(K)
```

主に、問題難易度と同じ logit 尺度で回答確率を計算するために使います。

### 数値安定化

`logit(0)` と `logit(1)` を避けるため、logit 変換の直前だけ次を使います。

```text
K_safe = clamp(K, ε, 1 - ε)
```

この clamp は、保存されている真の `K` を変更しません。`ε` は学習・忘却モデルの研究パラメータではありません。数値計算上の安定化定数です。具体的な実装値は、実装の Issue で決めてよいです。

### 更新空間

World A、World B-E、World B-P の主たる学習状態更新は `K` 空間で行います。World B-E と World B-P の忘却更新も `K` 空間で行います。

学習更新の式と Learning Rate は Issue #4 で確定します。指数忘却・べき乗忘却の式とパラメータは Issue #6 / #7 で確定します。

### World C の例外

World C は、activation や memory trace など、`K` 以外の内部状態を保持してよいです。World 間比較のため、外部から取得できる canonical latent competence として `K ∈ [0, 1]` を提供します。内部状態から `K` をどう導出するかは Issue #11 で確定します。

`a` や activation の形式そのものは棄却しません。World C などの内部状態として使う余地は残します。棄却するのは、`a ∈ ℝ` を全 World 共通の保存状態にすることです。

### 採用理由

- World A、World B-E、World B-P の学習と忘却を、同じ有界な状態空間で表せる。
- Mastery threshold を、`[0, 1]` 上の閾値として定義しやすい。
- `a = logit(K)` により、問題難易度と同じ logit 尺度へ接続できる。
- 標準難易度 `d = 0` では、基礎正答確率が `K` と一致する。
- BKT、PFA、HLR のいずれかの内部状態を、生成世界の真値として採用せずに済む。

### 棄却した案

`a ∈ ℝ` を全 World 共通の保存状態とする案は採用しません。

- 現在候補となっている学習式と忘却式は、`K` 空間で自然に定義されている。
- 学習と忘却のたびに `a → K → a` の変換が必要になりやすい。
- mastery と retention の解釈が、`K` より間接的になる。

## 世界

### World A — 学習のみ（Learning-only）

最小のベースライン（Baseline）です。

- 学習はある
- 忘却はない
- 間隔効果（spacing effect）はない

World A は、知識の変化が練習による学習だけのときにも、伝播のパターンがすでに現れるかを確認します。学習状態の更新は `K` 空間で行います。更新式は未確定です。

### World B-E — 指数忘却（Exponential Forgetting）

主分析の候補です。

- 逓減する学習
- 指数忘却
- 明示的な時間

忘却更新の候補：

```text
K(t + Δ) = K(t) exp(-λ Δ)
```

この式は、忘却の段階の候補です。世界の仕様全体ではありません。忘却更新を行う空間は `K` です。式とパラメータは Issue #6 で確定します。学習の段階と `Δ` の分布は未確定です。

### World B-P — べき乗忘却（Power-law Forgetting）

主分析の候補です。

- 逓減する学習
- べき乗忘却
- 明示的な時間

忘却更新の候補：

```text
K(t + Δ) = K(t) (1 + λ Δ)^(-β)
```

この式は候補です。忘却更新を行う空間は `K` です。式とパラメータは Issue #7 で確定します。

World B-E と World B-P は、人間の記憶にとってどちらの忘却曲線が正しいかの順位付けではありません。両方を走らせるのは、伝播の結果が忘却の族に依存するかを問うためです。

### World C — 認知的・間隔のストレステスト（Cognitive / Spacing Stress Test）

式が決まるまでは、主分析の世界ではなくストレステストです。

- 練習履歴への依存
- 活性化（activation）または痕跡（trace）に基づく状態
- より明示的な間隔効果
- Pavlik–Anderson および ACT-R 系の間隔モデルを参考にする

World C の式は固定していません。式を採用するには、内部状態、活性化または痕跡の更新、その状態から canonical な `K` をどう導出するかを書いた、別の設計メモが必要です。導出は Issue #11 で確定します。`K` 以外の内部状態を保持してよく、外部へ出す canonical latent competence は `K ∈ [0, 1]` です。

## 問題難易度と基礎正答確率

問題難易度 `d` は実数の logit 尺度に置きます。基礎正答確率の候補は次です。

```text
p_base = sigmoid(logit(K) - d)
```

`d = 0` のとき `p_base = K` です。これを、状態尺度の解釈上の基準として記録します。logit の直前には `K_safe` を使います。clamp 後の値は、保存されている `K` ではありません。

Guess / Slip を含む最終的な回答生成式は、Issue #2 で確定します。ここでは回答モデル全体を確定しません。

次は、これまで挙げていた有力候補であり、採用済みの仕様ではありません。

```text
P(correct) = G + (1 - G - S) * sigmoid(a - d)
```

ここで `a = logit(K)` です。`a` は保存された潜在状態ではありません。

- `G` は当て推量（Guess）
- `S` はうっかり誤答（Slip / Lapse）
- `d` は問題難易度（Item Difficulty）

パラメータの値、事前分布、`G` と `S` が問題ごとまたは学習者ごとに変わるかどうかは、未設定です。

## 学習増分

World A、World B-E、World B-P の主たる学習状態更新は `K` 空間で行います。更新式と Learning Rate は Issue #4 で確定します。次は候補であり、確定した式ではありません。

知識の更新には逓減する利得を使います。際限なく加算する利得は候補にしません。

例：

```text
K+ = K + L (1 - K)
```

`L` は、この例では `(0, 1]` の学習率の項です。履歴、時間、現在の問題への依存は世界ごとに異なり、まだ固定していません。

主たる世界では、学習増分（Learning Gain）を、回答が正しかったか誤りだったかから直接取りません。基本の因果は次です。

```text
practice opportunity → learning
```

日本語では「練習の機会 → 学習」です。

練習の機会が知識を更新します。観測された正誤は回答モデルの出力であり、増分を決める入力ではありません。

次は感度分析（Sensitivity Analysis）であり、主たる世界からは分けておきます。

- 検索に成功したときの上乗せ（successful retrieval bonus）
- 誤答にフィードバックが付く場合（incorrect response plus feedback）
- その他の、正誤に依存する学習規則（correctness-dependent learning rules）

感度分析用の世界は、これらの修飾のどれを加えるかを述べます。ラベルなしに、主たる推定と混ぜません。

## 実装の位置づけ

研究基盤の実装言語は Julia です。入口は `src/AdaptiveLearningSimulation.jl` です。依存関係は `Project.toml` と `Manifest.toml` で固定します。生成学習者の状態更新と回答生成は、Julia 側にはまだありません。

`src/als/generative/` は Python の試作です。正式な研究実装ではありません。試作は `ConceptState.ability` を保存値とし、`competence` を `sigmoid` で導出しています。これは、保存する正本を `K` とし、`a = logit(K)` を派生値とする今回の仕様と一致しません。試作を、この仕様の実装対応として読みません。試作の削除は Issue #39 の範囲であり、この決定ではコードを変更しません。
